Key Features

Core capabilities of the Loops Offline Check-in V2 application

Design Goal

Ground staff must be able to check in passengers even when the venue has poor or no internet. All booking data is downloaded at session start and stored locally; check-in actions are queued and synced to the backend as soon as connectivity allows.

Core Features

📴

Offline-First Operation

The app downloads all booking data for a route at login and stores it in IndexedDB. Every check-in action works entirely locally — no live internet required during the event.

  • Data survives page reload
  • Works in airplane mode
  • Queues pending syncs automatically
📷

QR Code Scanning

Uses the device camera via @zxing/library to scan passenger booking QR codes. Each QR encodes the booking orderNumber, which is matched against local IndexedDB data instantly.

  • Real-time camera feed
  • Instant local lookup (no API call)
  • Handles already-used tickets
📞

Phone Number Check-in

Alternative check-in method for passengers whose QR code is unavailable or damaged. Staff enters the passenger's phone number and the system searches local bookings.

  • Multiple bookings per phone supported
  • Shows booking selection UI
  • Partial seat check-in (e.g. 1 of 3)
🗄️

IndexedDB Local Storage

Three object stores persist all session data in the browser's IndexedDB, surviving refreshes and connectivity loss.

  • routecode — active route identifier
  • booking — all passenger bookings
  • listticket — pending check-in queue
🔄

Background API Sync

A setInterval timer runs every 5 seconds on active pages. When the pending listticket queue is non-empty and connectivity is available, it batches and PATCHes all check-ins to the backend in one call.

  • 5-second polling interval
  • Clears queue on success
  • Updates local booking state
📊

Live Progress Dashboard

The main dashboard shows a circular progress indicator with checked-in vs. total seats, updated from the local IndexedDB state in real time as check-ins are confirmed.

  • Checked-in seat count
  • Remaining seat count
  • Active route code display
👥

Passenger List

A dedicated /passengers page lets staff browse all bookings for the route, see check-in status per passenger, and manually select bookings to process.

🪑

Partial Seat Check-in

For group bookings with multiple seats, the CheckInModal presents a seat counter (+/−) so staff can board a subset of the group's seats at a time, tracked in checkInHistory.

📱

Progressive Web App

Installable on any mobile device's home screen via the web app manifest. Runs in standalone mode (no browser chrome) and loads instantly from the service worker cache.

  • Standalone display mode
  • Custom app icons
  • Portrait orientation lock

Check-in State Machine

VALID
available
→
PARTIAL
some seats boarded
→
USED

✕
NOT FOUND
no matching record

Status is derived by comparing checkInHistory seat sum against booking.seats
