Main Flow Diagram

/ (root)

1. Login — Enter Route Code

Staff enters the route code (e.g. "BKK-CNX-001"). App calls GET /bookings/adm/round/:code to fetch all bookings for that route.

IndexedDB

2. Save Data Locally

Clears old DB, then writes routecode, booking, and an empty listticket store. Redirects to /main.

/main

3. Dashboard

Loads booking data from IndexedDB and shows the circular progress indicator. Background sync timer starts (every 5 s).

/checkin

4. Check-in Hub

Staff chooses between QR Code Scanner or Phone Number lookup.

QR Code
/checkin

4a. Camera Scan

Opens device camera. Scans orderNumber from QR. Looks up in local booking array.

Phone No.
/phone-checkin

4b. Phone Search

Staff types passenger phone. QRProcessor.processPhoneNumber() filters local bookings by telephoneNumber.

CheckInModal

5. Confirmation Modal

Shows booking details. For multi-seat bookings, staff selects how many seats to board. Staff taps Confirm.

IndexedDB + API

6. Write Locally & Sync

Appends entry to listticket, updates local booking state, calls PATCH /bookings/adm/check-in. On success, clears queue and writes updated booking back to IndexedDB.

/main

7. Return to Dashboard

Progress circle updates. Ready for next check-in. Background sync continues every 5 s.

Error / Edge Case Paths

Not Found

QR or phone does not match any booking in local data. Modal shows error state.

Already Used

checkinStatus = true (all seats boarded). Modal shows "Already has been used".

Multiple Bookings

Same phone number has >1 valid booking. Modal lists all; staff selects one.

API Failure

PATCH fails or offline. Entry stays in listticket queue and retries next interval.
