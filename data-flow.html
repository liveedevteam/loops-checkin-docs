Detailed Message Table

# From To Message / Action Notes
1 Staff (Login page) Backend API GET /bookings/adm/round/:code Fetches all bookings for the route. Requires internet.
2 Backend API Login page Booking[] JSON array Returns all bookings. App derives checkinStatus locally.
3 Login page IndexedDB clearDB() then write routecode, booking, listticket Old session data is completely wiped before writing new session.
4 Check-in / Phone pages IndexedDB getDataFromIndexedDB("booking") Loads booking array into React state on mount.
5 QRScanner / PhoneSearch In-memory state Filter booking.data[] by orderNumber or telephoneNumber Pure local lookup — no network call needed.
6 CheckInModal (Confirm) IndexedDB Push { orderNumber, seats } to listticket store Immediately persisted so it survives page reload.
7 Sync timer (5 s) Backend API PATCH /bookings/adm/check-in with { checkInCode, checkList } Batches all pending tickets. Skipped when queue is empty or offline.
8 Backend API Sync timer Updated Booking[] with new checkInHistory Contains the server-confirmed check-in records.
9 Sync timer IndexedDB Write merged booking back + empty listticket Booking state is now consistent with the server.

Offline Queue Strategy

📴 When offline
  • Check-in actions succeed locally
  • Entries accumulate in listticket
  • UI updates from local state
  • Sync timer fires but silently fails
  • Queue persists in IndexedDB across reloads
🌐 When back online
  • Next 5-second tick detects non-empty queue
  • Full batch is sent to the API in one PATCH
  • On success: queue cleared, local DB updated
  • Server and local state become consistent
  • Progress display refreshes from new data
